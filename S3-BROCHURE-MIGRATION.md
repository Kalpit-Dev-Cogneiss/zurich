# Moving Portfolio Brochures to S3 + CloudFront

## Current state

- Brochure pages live in `public/portfolio-brochures/<Folder Name>/*.webp` (863 pages, ~593MB, converted from the original JPGs at quality 85).
- `app/lib/brochureManifest.json` lists every folder's files in page order — generated by `scripts/generate-brochure-manifest.js`. This is what the site actually reads; it never touches the disk images directly.
- `app/lib/portfolioBrochure.ts` builds the `<img>` URLs the flipbook (`TurnJSBook`) uses:
  - If `BROCHURE_CDN_URL` is **not** set → serves from `/portfolio-brochures/...` locally.
  - If `BROCHURE_CDN_URL` **is** set → serves from `${BROCHURE_CDN_URL}/...` instead.
- `public/portfolio-brochures/` is gitignored — the raw images are not committed, only the manifest is. This keeps the repo small; the S3 bucket becomes the source of truth for the actual files.

So the only thing left to do is: upload the files, stand up CloudFront, and set one env var.

## 1. Create the S3 bucket

AWS Console → S3 → **Create bucket**
- Name: e.g. `zurich-portfolio-brochures`
- Region: same region as your EC2 instance (or closest to your users) for cheaper/faster origin fetches
- **Block all public access: ON** (leave it blocked — CloudFront will access it privately via OAC, not the public internet)

## 2. Upload the files

From the repo root, with the AWS CLI configured (`aws configure`):

**PowerShell (Windows):**
```powershell
aws s3 sync "public/portfolio-brochures" s3://zurich-portfolio-brochures/portfolio-brochures `
  --exclude "*.pdf" `
  --content-type "image/webp" `
  --cache-control "public, max-age=31536000, immutable"
```

**bash/zsh (macOS/Linux):**
```bash
aws s3 sync "public/portfolio-brochures" s3://zurich-portfolio-brochures/portfolio-brochures \
  --exclude "*.pdf" \
  --content-type "image/webp" \
  --cache-control "public, max-age=31536000, immutable"
```

(PowerShell's line-continuation character is a backtick `` ` ``, not `\` — using `\` throws "Missing expression after unary operator" parser errors.)

Notes:
- `--exclude "*.pdf"` skips the 3 leftover source PDFs (`Lush Meadows.pdf`, `Palladium Highstreet_Brochure.pdf`, `Skyline Excellent_BROCHURE.pdf`) — they aren't used by the site, no need to serve them.
- `--content-type "image/webp"` is required because `aws s3 sync` guesses content-type from extension inconsistently across CLI versions; setting it explicitly avoids browsers/CloudFront treating pages as `application/octet-stream`.
- `--cache-control "public, max-age=31536000, immutable"` — these files never change in place (a re-upload would use a new filename or you'd invalidate manually), so cache them for a year at the edge and in the browser.
- Keep the folder structure: `s3://zurich-portfolio-brochures/portfolio-brochures/<Folder Name>/<file>.webp` — this must match what's in `app/lib/brochureManifest.json` exactly, including spaces/case in folder names.

## 3. Create the CloudFront distribution

AWS Console → CloudFront → **Create distribution**
- Origin domain: select your S3 bucket
- Origin access: **Origin access control settings (recommended)** → create a new OAC → CloudFront will give you a bucket policy to paste into the S3 bucket's permissions (do this, or the distribution returns 403s)
- Viewer protocol policy: **Redirect HTTP to HTTPS**
- Cache policy: **CachingOptimized** (respects the `Cache-Control` headers set in step 2)
- Compress objects automatically: **Yes**

Wait for the distribution status to flip from "Deploying" to "Enabled" (~5-15 min). Note the distribution's domain, e.g. `d123abc456xyz.cloudfront.net`.

Optional: attach a custom subdomain (`cdn.yourdomain.com`) via an ACM certificate + Route53/DNS CNAME instead of using the raw `cloudfront.net` domain.

## 4. Point the app at it

On the EC2 box (or wherever `deploy/ecosystem.config.js` / PM2 reads env vars from), set:

```bash
BROCHURE_CDN_URL=https://d123abc456xyz.cloudfront.net/portfolio-brochures
```

Restart the app (`pm2 restart` per `deploy/redeploy.sh`). No code changes needed — `getBrochureImages()` in `app/lib/portfolioBrochure.ts` already branches on this env var.

Verify by opening a portfolio page with a brochure (e.g. `/portfolio/tsl`) and checking the flipbook's image requests in devtools go to the CloudFront domain.

## 5. Updating brochures later

When you add/replace pages for a project:
1. Drop the new `.webp` files into `public/portfolio-brochures/<Folder Name>/` locally.
2. Re-run `node scripts/generate-brochure-manifest.js` to refresh the manifest (commit this file).
3. Re-run the `aws s3 sync` command from step 2 (it only uploads changed/new files).
4. If you *replaced* an existing filename with new content, also invalidate that path so CloudFront drops the cached copy:
   ```bash
   aws cloudfront create-invalidation --distribution-id <DIST_ID> --paths "/portfolio-brochures/<Folder Name>/<file>.webp"
   ```
   (Not needed for brand-new filenames — those have never been cached.)

## Adding a brochure for a new project

1. Add the folder + webp pages under `public/portfolio-brochures/<Folder Name>/`.
2. Add `brochureFolder: '<Folder Name>'` to that project's entry in `app/lib/portfolioData.ts`.
3. Re-run the manifest script and S3 sync (steps above).

The 16 projects currently without a brochure folder just need these three steps whenever their brochure is ready — `[slug]/page.tsx` already renders the flipbook automatically whenever `brochureFolder` + manifest entries are present.
